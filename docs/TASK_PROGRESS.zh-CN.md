# 任务级进展对账：第一批实现

第二批已补充持久任务、尝试及证据写入归属，使用说明见工具参考中的 `redteam_task_run`。下文保留第一批能力边界；第二批首个可执行验收条件仅覆盖 HTTP 证据记录交付，不替代漏洞真实性或通用任务验收。

第三批已接入 `agent/status` / `agent/disposed` 与绑定会话的 `turn/end` 观察。新增 `task_attempt_runtime` 表只保存执行器关联、代际标记和恢复状态，不把持久 running 当作实时活动。用户停止取消对应活动尝试；普通轮次结束、卸载和绑定丢失要求核对，reconcile 不重放操作。已验收的记录交付不会因宿主卸载而要求重新执行。仍不主动调用宿主 cancel、杀进程或自动恢复未知操作。

事件载荷与 AgentStatus 已对照本地固定下载的官方 `@deepseek-ai/dsh-agent` 0.2.2-rc.1 / rc.2 类型声明核对；行为测试使用合成 Agent 与 SQLite，不等价于真实模型或桌面停止验收。

第四批已加入 task_plan / task_dependency / task_failure：可声明依赖、记录分类失败、查看当前路线，并只修改未完成任务的方法标签。依赖图拒绝环，验收失效沿传递依赖阻止后续启动；相同条件下重复失败不盲目重试，候选窗口之前排除等待任务。这里实现的是可追溯的局部调整及重试约束，不是已验证有效的自主策略生成；真实环境条件与模型决策质量仍需后续对照。

第五批已将分类失败接入现有本地知识检索，返回受限查询、来源覆盖和最多三条去重引用；原始原因和文档正文不自动进入任务提示。可显式记录绑定失败尝试的资料用途反馈，但不会将资料命中或自报反馈升级为任务成功。固定的 8 个合成检索夹具提供可重复开发对照，不调用模型、不等同真实任务收益。

第六批加入官方注册器集成测试与显式运行的真实模型微型对照，协议和结果见 `AUTONOMY_VALIDATION.zh-CN.md`。一对有效短任务中两组均产出合成证据，候选额外完成持久验收，但调用及 Token 更多；不据此宣称整体自主能力提升。

第七批补齐可选操作键与原子写入回执，避免“记录已提交、返回结果丢失”后的相同写入生成重复证据；回执读取不自动恢复运行。新增 24 个依赖任务、分类失败与路线修改、独立进程退出/重启及重复恢复的确定性夹具，详情见 `TASK_RECOVERY.zh-CN.md`。它验证本地持久链路，不是模型长时自主能力或桌面停止验收。

第八批按本机实际 `0.2.2-rc.3` 对齐默认适配目标、官方 fixture 和 CI，并直接加载已安装包验证注册/重载恢复。后续报告明确记录宿主版本，历史短样本仅追加身份追溯，不改写测量。收尾范围固定为本批、真实多阶段对照、整合与桌面验收三批，详情见 `AUTONOMY_ROLLOUT.zh-CN.md`。

第九批完成两次配对的真实模型三资产交付与原生 Session 跨进程接续：两组共同产物均成功，增强组额外对账、依赖及验收通过，但调用/Token 明显更多，不构成自主效果或效率提升证据。补充只读上游检查入口，并按用户要求清理已核实的旧备份；第十批改为不备份、不回滚的简化整合。协议及限制见 `AUTONOMY_MULTISTAGE.zh-CN.md`。

基线：beta `0a478de08bb53a63bc18f808af19a98d4a81eb54`。本批只增强现有任务卡、对账与交接，不新建执行循环、不更换模型、不修改桌面安装。

## 行为

- `redteam_next_action` 对 `asset #ID` / `vuln #ID` 任务在 `focus.before.task_scope` 附加目标绑定及内容指纹。
- `redteam_progress_check` 与 `previous_task` 交接重新读取同一目标，输出 `task_progress`；全局统计和原字段仍保留。`task_measurable_change` 与原全局 `measurable_change` 分开。
- 当前目标的内容修正即使没有增加记录数，也可识别；无关目标的记录或全局分数增长，不再单独推动当前任务交接。
- 关联记录减少、目标不存在、无内容变化时暂缓核查；明确 `blocked` / `inconclusive` 的既有语义保留。
- 旧基线及其它目标类型保持原逻辑，不把未覆盖任务谎报成任务级验证。

资产覆盖原始资产行、端口、服务、指纹、关联漏洞、直接与间接关联的 HTTP 证据。漏洞覆盖原始漏洞行及其 HTTP 证据。使用 SQLite 保存点取得一致读视图，逐行计算 SHA-256，不截取前 100 条，不截断报文正文；模型只收到指纹与计数，不收到原始内容。忽略单纯时间戳与记录者元数据刷新。

## 验证范围与限制

自动测试覆盖等长证据修正、无关目标变化、全局分数增长、超过 100 条证据、删除、缺失、范围不匹配、嵌套事务、旧基线和注册工具调用链。

`task_progress.verification` 明确为 `not-performed`：记录变化不等于任务验收通过、漏洞确认、有效得分，也不能区分同一目标上的不同执行者。第二批单独输出 `task_run.assessment`，仅核对该尝试经指定写入路径创建的记录；未归属的旧记录及其它尝试记录不能作为它的交付。

未进行真实模型长任务、真实桌面验收或性能收益测量。大目标证据量对指纹耗时的影响仍需测量；流式读取不等于已证明低延迟。
