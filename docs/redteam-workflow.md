## 实现

### 1. 完整查询，而不是静默截断

`assets` / `vulns` API 及对应查询工具支持 `offset`，返回：

```json
{"total":405,"limit":400,"offset":0,"returned":400,"hasMore":true,"nextOffset":400,"items":[]}
```

上例只示意元数据，实际 `items` 含本页记录。默认每页 200，资产每页最多 2000、漏洞每页最多 1000；这些是内存/响应大小边界，不是结果总数上限。`limit` 必须为安全正整数，`offset` 为安全非负整数，错误值不再变成 SQLite 的无限制查询。数字字符串只接受十进制整数字面量。

- 资产排序加入唯一 ID 决胜条件，避免 IPv6 或同优先级记录在翻页时排序不稳定。
- 前端资产页每页 400、漏洞页每页 200，显示范围、总数与翻页按钮。
- 切换演练或筛选立即重置分页；旧请求、卸载后的请求不再覆盖新结果。
- 删除末页数据后回到最后一个有效页；失败明确显示错误，不保留旧列表冒充新结果。
- 遗留报告加载器遍历所有分页，不再请求 2000 后只拿到 1000。报告入选规则不变。
- OFFSET 分页不是跨多次请求的事务快照：并发插入/删除期间可能移动页边界，刷新后应重新遍历。

### 2. 并发状态与预留

- 共用工具层的旧版 `activity` / 新版实时 `Agent.status` 适配，不再因新版目录缺少 `kind` 误报零运行。
- 同一主会话内对实时子任务和本地预留取去重并集；重复占位键幂等，释放时清理对应关联。
- 注册表缺失、单个主会话查询失败、子任务状态未知，均明确标记为未知或已观察下限。`free` 此时为 `null`，不能当作验证后的可用容量。
- 多个主会话分别显示占用/上限/剩余，不把每会话上限减去跨会话总占用。
- 预留是进程本地信息，不宣称跨进程任务锁、持久化队列或崩溃恢复。外部派发在 start 事件前失败时，需要调用者按稳定 key 显式释放，不能靠超时猜测任务结束。
- 写并发设置采用原子替换，保留无关配置；原文件格式损坏时拒绝覆盖。缺少明确库目录时不向当前目录写入设置。设置写入锁在硬崩溃后可能残留，必须核实原写入进程后再处理，不自动夺锁。

### 3. 数据质量：只读、不过度承诺

新增 `redteam_data_quality` 工具、`dataQuality` API 和“数据质量”页。

检查缺失证据字段、已确认但无证据记录、空 HTTP 证据、孤立的资产/漏洞/截图关联。只输出计数与问题码，不输出凭据、请求响应或截图内容。独立只读 SQLite 连接与读取事务，不迁移旧库，不修复或修改记录。SQLite 的 WAL 模式可能创建或维护 `-wal`/`-shm` 共享辅助文件，故不承诺零文件系统写入；不会用 immutable 模式忽略尚未 checkpoint 的已提交数据。

`scope: stored-record-metadata`、`validatesFindings: false`：没有命中这些检查，不等于漏洞已验证；存在截图记录，也不代表图片文件或内容有效。显式错误演练 ID 报错，不回退到另一个目标。

### 4. 报告可交付性

导出命令创建独立子目录，不清空指定输出目录，不覆盖旧报告；只复制报告实际引用的截图，拒绝越界路径、符号链接、非普通文件和缺失引用。输出 Markdown、引用截图与含逐文件 SHA-256 的 JSON 清单；失败只清理本次独占创建的文件。重复运行可保留多个版本。

```powershell
node scripts/export-engagement-report.mjs --root "[DATA_ROOT]" --engagement "[ENGAGEMENT_ID]" --out "[EXPORT_PARENT]"
```

建议如上显式给出全部路径和演练 ID。为兼容旧调用，省略 root 时依次使用 REDTEAM_HOME、DSH_HOME/redteam、用户默认 .dsh/redteam；省略 engagement 时使用当前演练，省略 out 时使用当前工作目录。参数缺值、重复或未知选项均报错。程序接口可导入且不会立即导出；数据库句柄在 finally 中关闭。

## 安装与回退

先备份选定 profile 的 `package.json`、lockfile、`cordis.patch.yml` 及生产数据，再按历史维护文档安装本轮 `.tgz`；不要把本地测试 HOME 当作生产 HOME。新预览只通过显式选择的 profile 安装，禁止直接整体覆盖宿主目录。

回退时在同一 profile 安装保留的 `1.1.71-compat.2` 包，必要时恢复上述配置备份，然后重启对应宿主。本轮没有新增数据库迁移；数据文件本身不应随包卸载删除。安装后的实际模型、桌面交互和长期运行仍需分别验收。
