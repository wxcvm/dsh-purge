# 第九批：真实模型多阶段、原生会话接续与上游检查

日期：2026-11-13。来源基线：第八批 `809a736fb00f239a197b65de1e9946d9c3aa8dd0`，加本批工作树。执行宿主明文版本为 `0.2.2-rc.3`，前后入口/清单及 EXE 元数据一致；远端实际模型修订不可见。

## 协议与证据等级

- 同一请求路由 `deepseek-account / deepseek-flash / low`；每次调用 120 秒上限、32 次允许工具调用，工具目录白名单与守卫共同约束，无系统命令、文件读取或外部目标访问。
- 一个受控场景，三资产按 1→2→3 各交付一条精确请求/响应。两次配对重复，顺序为 baseline/candidate，再 candidate/baseline，共四个会话、八个真实模型调用。
- 第一阶段只交付资产 1 后暂停。增强组还建立依赖、完成记录验收并启动资产 2 的未完成尝试；第一条写入注入一次 ETIMEDOUT，且在实际写入之前拒绝。
- 首进程正常结束后，下一进程使用官方 `--session-id` 采用同一持久 Session。第二阶段只提示继续，不重复完整任务正文，由已保存会话及工具状态提供上下文。增强组先核对、显式 reconcile，再继续归属、提交与验收。
- 两组共同标准均为退出后只读检查 SQLite：暂停时记录数量必须为 [1,0,0]，最终必须 [1,1,1]，请求/响应精确匹配。增强组另外核对依赖和各尝试记录完整性。基线没有增强能力不算共同任务失败。
- 记录每阶段独立工具 trace，避免恢复后把旧调用再次计数。会话 ID 只在运行内存使用，不进入交付报告；不发布思考、参数或最终全文。

**这是计划暂停后的原生会话跨进程接续，不是任意位置崩溃、原生上下文压缩、断电或长时间运行测试。** 任务仍有明确阶段指令，不证明模型能从宽泛目标自行构建有效战略。

## 实测结果

| 每个两阶段会话的观察 | baseline | candidate |
|---|---:|---:|
| 样本数 | 2 | 2 |
| 共同产物成功 | 2/2 | 2/2 |
| 原生 Session 采用成功 | 2/2 | 2/2 |
| 增强组依赖、对账及记录验收 | 不提供 | 2/2 |
| 平均工具调用 | 13.5 | 26 |
| 平均两阶段耗时 | 36.609 秒 | 47.743 秒 |
| 平均 SDK totalTokens，含缓存计数 | 70,256 | 184,867 |

四个会话各观察到一次注入错误；增强组每次在恢复阶段调用一次 reconcile。记录数量均准确，没有重复交付资产 1，也没有白名单外调用。入口指纹稳定，所有阶段的模型调用与工具守卫 trace 对齐。

**观察到的是额外可核对状态与跨进程接续能力，不是整体自主成功率提高。** 增强组调用和 Token 更多；样本小、场景单一、缓存/顺序效应未消除，不能据此宣称提速或降本。机器记录：`validation/autonomy-multistage-20261113.json`，原始测量不因最终测试更新而重写。
