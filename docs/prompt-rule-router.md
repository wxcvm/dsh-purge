# Purge 提示词规则路由 · 发版前验收

实现已通过 [PR #330](https://github.com/wxcvm/dsh-purge/pull/330) 合并到 master；当前文档只记录可重复验证的事实。合并不代表已在真实 Windows Harness 窗口完成安装与点击验收。

## Agent 预设的直观启停（新版界面）

- 「提示词管理」默认使用左右分栏：左侧直接编辑全局正文，右侧为局部规则卡片与选中规则编辑器；预设控制放在每份正文下方，关键词/模型和厂商黑白名单、会话锁定、预览默认折叠。
- 每份提示词可逐个勾选 **标准 standard、PTC ptc、极简 minimal、创造 cordis、红队 redteam**。注意创造模式底层 ID 为 `cordis`，历史 `code` 兼容识别为 `ptc`。
- 「未列出的预设也注入」是独立兜底开关，便于自定义 Agent 预设；明确取消某个内置预设的勾选优先于兜底。宿主无法提供当前预设 ID 时，不将其误判为“未列出的已知预设”。
- **红队仍独立**：红队正文继续读取 `prompt-inject.md`；普通全局/局部提示词只有明确勾选「红队」才作为附加正文生效，不会把红队正文当作普通全局提示词。
- 不改变原有模型/Provider/Session 黑白名单；预设勾选和高级名单的限制会叠加应用。点击「保存」后生效，未保存修改不会影响实际注入。

## 新版：全局、局部与红队分离

- **红队预设**只使用独立的 `prompt-inject.md`，与“通用全局”无关；普通模式即使任务文字提到红队，也不会自动进入红队模式。红队配置有独立开关，手动锁定仍必须尊重禁用状态。
- **通用全局提示词**为独立的 `global` 配置（默认关闭，避免升级时自动改变普通会话）。开启后对标准/极简会话匹配，正文保存到独立 `prompt-profiles/global.md`，不改旧红队正文。
- **局部提示词**可以建立多条，互相独立启停；关键词命中或开启白名单并设置目标时参与路由。所有适用规则按“全局优先、局部 priority 降序、ID 稳定排序”合并到**一个** Purge 段，保留宿主原生提示词/工具/上下文。
- **逐条白名单/黑名单**分别有启停开关。目标支持模型、Provider、Session ID、Agent 预设；同一维度多条取“或”，不同白名单维度间取“且”；任一黑名单维度命中则排除该条规则。黑名单优先；开启但未填任何白名单条目时该规则不注入。空缺的实际模型/Provider 不会被假定匹配。
- 名单条目不要求用户使用额外模型；支持精确 ID、`*` 通配符及英文大小写不敏感匹配。保存字段为 `scope`、`allowEnabled`、`allowTargets`、`blockEnabled`、`blockTargets`，旧配置字段继续有效。
- 旧版“会话锁定某一条 / none”的覆盖行为保留以兼容既有数据；新加“仅在此会话暂停某条”独立保存至 `prompt-session-overrides.json`，不会同时暂停其它局部规则。
- 在“提示词管理 → 自动匹配与会话”中可直接点击“新建提示词规则”进入本地草稿编辑，**只有保存后才写入与注入**；新规则可选择“全局 / 局部”，分别配置名单开关及正文。无需先填写英文 ID；ID 可自动生成，错误/保存状态在顶部可见。
- 同源预览接口可提交 `text`、`preset`、`model`、`provider`、`sessionId`，返回每条规则命中/被排除的原因。预览不调用模型，也不意味着真实宿主已识别模型 ID。

## 本地配置文件

`$DSH_HOME/dsh-purge/prompt-profiles.json`（不存在时使用内置默认配置）：

```json
{
  "profiles": [
    {
      "id": "research",
      "name": "资料研究",
      "enabled": true,
      "priority": 60,
      "keywords": ["资料整理", "研究报告"],
      "excludes": ["不要生成报告"]
    }
  ]
}
```

每个自定义提示词正文为独立 Markdown 文件：

```text
$DSH_HOME/dsh-purge/prompt-profiles/research.md
```

标识只允许英文小写字母开头及英文小写字母、数字、下划线和连字符，以确保文件路径确定。匹配忽略英文大小写，关键词采用确定性子串匹配，模型/厂商等名单采用精确或通配符匹配；不调用 AI。

会话手动锁定数据存放在 `$DSH_HOME/dsh-purge/prompt-session-locks.json`。代码接口为 `setSessionPromptLock(home, sessionId, profileId)`；`profileId=null` 恢复自动选择，`profileId="none"` 表示该会话不注入 Purge 提示词。

清洗台「提示词管理 → 通用与局部提示词」（默认页签），支持新增、编辑、启用/禁用、删除自定义配置、命中预览和会话锁定。「红队专用提示词」页签保留对现有 `prompt-inject.md` 的编辑。切换页签只改变分类展示，不迁移正文或改变运行时注入规则。

新增同源管理端点：`GET /dsh-purge/prompt-profiles`、`POST /dsh-purge/prompt-profiles`，后者支持 `save` / `delete` / `preview` / `lock` / `unlock`。匹配预览只调用本地路由规则，不发起模型请求。

- 已在清洗台新增「提示词库」：新建、编辑、禁用、删除、命中预览、会话锁定及解除锁定；原「提示词」页面和 `prompt-inject.md` 不迁移。

- 轻量调度仅提供任务类型、能力和可选子代理建议，**不自动执行工具，也不新增模型依赖**。

## 发版前桌面手工验收（尚未执行）

在隔离的 Windows Harness Desktop 环境中测试，保留现有配置备份；不要直接覆盖正在工作的正式安装。使用无敏感信息的本地示例任务。

1. 打开清洗台「提示词管理 → 自动匹配与会话」，新建 `route-smoke`，设置关键词 `演示路线检查`、示例正文 `ROUTE_SMOKE_TEST`，保存后刷新。确认正文、优先级和启用状态持久化。
2. 在标准预设中发送 `演示路线检查`，检查真实宿主 assembled prompt 是否**仅出现一次** `ROUTE_SMOKE_TEST`，没有历史红队段；切回「你好」确认无命中时恢复宿主原生提示词。
3. 在同一会话手动锁定为 `writing`，确认覆盖关键词路由；改为 `none`，确认不注入 Purge 段；恢复「自动选择」再验证能命中。切换到另一会话并返回，核对锁定显示与实际会话 ID 一致。
4. 切到红队预设，核对仍读取原 `prompt-inject.md`，且没有因为新提示词库而改写文件；再切回标准/极简，检查锚点和残留。
5. 派生一个只读子代理，先验证默认继承父会话提示词，再显式锁定子会话以覆盖；不改变父会话的锁定状态。
6. 用一段正常响应、一段明确拒答文本和一次受控的本地请求失败测试「诊断中心 → Provider 与运行记录」；仅核对分类来源是否分开，不用实际高风险目标。
7. 完全退出并重启 Desktop，确认提示词库配置持久化、界面可保存、历史对话和已有工具/技能仍可访问；再核对卸载或回退是否保留用户数据。清理本轮测试用自定义提示词。

**未完成项不能写成通过。** 如宿主无法显示最终 assembled prompt，就记录「不可直接观测」，结合调试日志和可获取的宿主证据；不能凭模型一句话推断成功。

## 本机可视化路由开关（#369）

在当前 Harness Web/桌面宿主的本机 HTTP 地址访问 `/dsh-purge/prompt-routing`，可分别设置：

- `bundledDefault`：普通预设无规则匹配时使用内置稿，默认关闭。
- `redteamTaskRoute`：在普通预设下按任务识别红队规则，仍遵循已有的会话暂停、预设及模型/Provider 黑白名单，默认关闭。
- `modelAdaptive`：只在当前请求可识别的模型家族下启用自适应回退，默认关闭。未知模型不会自动兜底。

设置通过同源 `/dsh-purge/prompt-routing-settings` 读写，落盘 `$DSH_HOME/dsh-purge/prompt-routing.json`，保存后立即更新当前插件运行实例，重启重新加载；无需编辑已有提示词规则。旧版宿主若不支持插件 Web 路由，该页面不可用，不能据此推断设置已经生效。

诊断报告中的 `stage=assembled` 只表示此插件返回的 sections 中注入段非空且置顶；`delivery=unverified` 表示还没有从模型实际请求边界得到证据。不能把这两者混为一谈。
