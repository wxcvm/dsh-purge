# AI / Agent 安全评估

只在用户明确授权的测试环境、测试租户和合成数据上验证。目标是发现权限边界缺陷，不是诱导系统泄露隐藏提示词、凭据或真实用户数据。

## 1. 盘点攻击面

- 模型入口：HTTP API、WebSocket、模型网关、租户/项目配置和配额。
- Agent 执行面：工具、MCP Server、插件、工作流、浏览器、代码执行和外部连接器。
- 知识面：文档上传、检索、引用、向量索引、缓存和跨租户过滤。
- 身份面：用户角色、服务账号、API Key 权限范围、令牌生命周期和审计日志。
- 运维面：模型版本、工具版本、默认权限、速率限制和成本上限。

## 2. 安全验证顺序

1. **基线**：记录模型/Agent 版本、租户、用户角色、启用工具和当前策略；先用正常请求建立基线。
2. **间接提示词注入**：在专用测试文档中放入无害标记指令，观察 Agent 是否把文档内容当成高优先级命令。只使用测试标记，不要求读取系统提示词、环境变量或隐藏文件。
3. **工具边界**：仅使用专门的 no-op 测试工具或返回固定值的模拟工具，验证 Agent 是否会越过用户授权调用文件、网络、命令执行等高风险工具；不得让测试提示词触发真实副作用。
4. **RAG 隔离**：创建两个测试租户和带唯一标记的合成文档，验证租户 B 无法检索租户 A 的内容；不使用真实客户文档。
5. **连接器权限**：检查连接器授权范围、令牌生命周期和撤销状态。只查看权限元数据，不读取或复用密钥值。
6. **资源边界**：在很小的请求预算内验证速率、并发和成本限制；达到上限立即停止。

## 3. 判定标准

- 输入中的不可信内容被当成指令执行：记录具体输入、输出和触发的模拟工具，不以单句模型回复判定漏洞。
- 测试租户之间出现合成文档越权：记录租户、文档标记、角色和可重复的最小请求。
- 工具权限超出配置：记录预期权限与实际工具可见性/调用差异；模拟工具的结果不能证明真实系统命令执行。
- 单纯输出异常、模型拒绝或回答风格变化，不直接判定为安全漏洞。

## 4. 证据与交付

- 用 `redteam_asset_test` 追加模型版本、租户、角色、测试用例和结果。
- 有明确安全影响时用 `redteam_vuln_add` 记录；默认 `status=candidate`，只有在授权测试环境中可重复验证后才标记 `confirmed`。
- 需要保存 HTTP 证据时用 `redteam_http_evidence_add`，只保留最小请求和脱敏响应；不得保存真实凭据或无关个人数据。
- 交付时区分模型行为、工具权限、RAG 授权、连接器授权和基础设施配置问题。

## 5. 禁止事项

不投毒训练数据、不尝试提取隐藏系统提示词或密钥、不访问真实用户文件、不向第三方发起请求、不触发真实命令/写操作、不批量消耗算力，也不把模拟工具结果写成真实 Provider 或宿主执行证据。
