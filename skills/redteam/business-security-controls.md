# 业务安全防护基线

## 适用边界

- 用于防御性架构审查、代码审查和授权预发布环境的回归测试。
- 测试数据必须是合成账户、合成订单和虚拟余额；支付流程使用 mock provider。
- 不访问真实用户数据，不触发真实扣款、提现或资金转移，不在未授权生产系统上验证。
- 本清单是审查参考，不代表目标存在漏洞；每项结论都需要代码、配置或隔离测试证据。

## 1. 身份、对象与租户授权

- 每次请求由服务端会话或已验证令牌确定主体，不信任请求体中的 userId、ownerId、role 或 tenantId。
- 对每个对象执行资源级授权；查询和更新都必须带服务端确定的所有者或租户条件。
- 代理、组织和租户层级关系由服务端数据计算，不能由客户端提交的层级字段决定。
- 默认拒绝；未授权时不返回对象内容或敏感存在性信息。
- 回归测试：使用两个合成用户和两个合成租户，验证跨用户、跨租户的读取和写入均被拒绝，且数据库状态不变。

## 2. 字段白名单与权限边界

- 使用专用请求 DTO，只允许业务操作需要的字段进入写入逻辑。
- role、balance、tenantId、ownerId、审核状态和系统标记由服务端控制。
- 对敏感字段实施字段级授权；普通资料更新不能隐式改变权限或资金属性。
- 回归测试：提交未知字段或只读字段时应明确拒绝或忽略，并验证持久化记录没有变化。

## 3. 订单状态机与支付回调

- 在服务端定义合法状态迁移；客户端不能直接决定订单已支付、已退款或已完成。
- 回调必须验证可信渠道签名、事件身份和时间窗口；来源 IP 限制只能作为纵深防护，不能替代签名验证。
- 金额、币种、商户和订单归属以服务端订单记录为准，回调字段只用于一致性核对。
- 重复事件必须幂等：同一事件或订单状态迁移只产生一次账务副作用。
- 定期对账渠道流水与本地账本，异常差额进入告警和人工复核。
- 回归测试：在 mock provider 下覆盖有效、无效、过期、重复和金额不一致事件；不连接真实支付渠道。

## 4. 幂等、并发与账务一致性

- 对创建、领取、扣减、退款等写操作使用业务幂等键，并在数据库建立唯一约束。
- 余额与订单变更放在同一事务；按业务需要使用行锁或乐观锁，避免并发覆盖。
- 金额使用整数最小货币单位或可靠的定点数表示；服务端校验正负、精度、范围和币种。
- 账本记录不可被普通业务接口静默覆盖；更正通过可审计的冲正或补偿记录完成。
- 回归测试：在测试数据库并发提交相同业务事件，验证只有一次有效状态迁移和账务记录。

## 5. 密码重置与 OAuth 生命周期

- 重置令牌使用密码学安全随机值，绑定单一用户、短时有效、一次性使用，并在成功后失效。
- 令牌不写入普通日志；密码或身份变更后，按策略撤销旧会话和旧令牌。
- OAuth redirect URI 使用精确白名单；state 必须校验且一次性使用，授权码流程启用 PKCE。
- 回归测试：覆盖过期、重复使用、用户不匹配和未登记 redirect URI，均不得改变账户状态。

## 6. 隐私、报表与数据导出

- 列表、报表、附件和导出接口执行与页面相同的对象级、租户级权限检查。
- 按任务需要最小化字段和记录范围；身份证件、银行卡、会话标识等敏感字段默认脱敏。
- 对大批量导出设置权限、速率和审批策略；记录操作者、范围、时间和结果摘要。
- 日志保留排查所需的请求 ID 和决策信息，不记录密码、令牌、完整支付凭据或不必要的个人信息。
- 回归测试：使用合成记录验证导出范围、脱敏结果和审计记录，不读取真实个人数据。

## 7. SSRF 与服务端出站请求

- 对回调校验、图片抓取和 URL 导入等功能优先使用明确的域名白名单。
- 校验解析后的 IP、重定向目标和最终连接地址；拒绝回环、链路本地、私有网络及云元数据地址。
- 配合出站网络策略限制服务端可访问的网段和端口；设置连接、读取超时与响应大小上限。
- 回归测试使用本地 mock 服务和固定 DNS 夹具，不连接真实内网或云元数据端点。

## 8. 浏览器、Cookie 与 WebSocket

- CORS 只允许明确的可信 Origin；携带凭据时不能使用通配来源。
- 状态变更请求使用 CSRF 防护，并正确设置 Secure、HttpOnly、SameSite Cookie 属性。
- WebSocket 在握手时认证，并对每个订阅频道再次检查用户、租户和资源权限；会话失效时关闭关联连接。
- 回归测试使用本地浏览器夹具和合成用户，验证跨源读取、跨频道订阅和过期会话均被拒绝。

## 9. 存储、密钥与发布产物

- 对象存储和备份默认私有；使用最小权限的服务身份和短期凭据。
- 不把 API 密钥、私钥、数据库连接串或内部凭据打包进前端源码、source map 和发布产物。
- 发现泄露后撤销并轮换凭据，同时检查访问日志和受影响范围。
- 回归测试在构建产物上执行秘密扫描，并验证匿名访问策略。

## 10. 证据与验收

每项审查结论至少记录：

- 受审系统、版本、环境和授权范围；
- 相关代码位置或配置项；
- 合成测试的前置条件、预期结果和实际结果；
- 是否产生状态变化，以及如何确认没有产生副作用；
- 修复责任人、复测结果和未解决风险。

把“设计上有控制”“测试中观察到控制生效”和“生产环境已验证”分开记录。缺少证据时标记为未知，不推断为安全或漏洞已确认。
