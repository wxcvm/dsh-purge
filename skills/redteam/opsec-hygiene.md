# 演练安全与收口

这里的 OPSEC 指降低误操作和业务风险、保护证据与隐私、确保操作可审计；不用于隐藏来源、规避检测或掩盖活动。

## 1. 开工前

- 明确书面授权主体、允许域名/IP/CIDR、测试账号、供应商边界、禁止事项和时间窗。
- 用 `redteam_scope_review(allowed=...)` 对已登记资产做离线范围核对；该工具不验证所有权，范围仍以用户授权为准。
- 为每类测试设定请求速率、并发、总量和超时；从最低强度开始。
- 确定业务联系人、停止信号、回滚联系人和数据保留期限。
- 只使用测试账号和合成数据；真实个人信息只在任务明确要求且具备合法授权时最小化处理。

## 2. 运行中

- 只做本次目标所需的最小请求；不通过轮换出口、伪造来源头或随机 User-Agent 来规避防护。
- 遇到 WAF/封禁、账号锁定、延迟异常、错误率上升、服务不稳定或范围不确定，立即停止该项测试并记录。
- 保留目标侧审计日志和测试时间线；不得清理日志、删除告警或关闭监控。
- 不把凭据、令牌、私钥、个人信息和完整生产数据写入对话、普通日志或 Git 仓库。
- 写操作只允许在单独授权的测试环境中进行，并先记录原值、回滚步骤和验证方法。

## 3. 自有资源收尾

交付前逐项核对本次测试创建的本地监听、回调服务、测试账号、临时文件、隧道和云资源。只回收由本次测试创建且用户明确允许回收的资源；保留用户要求保留的项目并记录原因。不要把“清理”理解成删除目标日志或抹去证据。

## 4. 记录与交接

- 用 `redteam_asset_test` 追加测试窗口、请求预算、停止原因、遗留项和最终状态。
- 用 `redteam_cleanup(op=add)` 记录本次测试创建的临时资源；交付前用 `op=list` 核对 open 项，完成后用 `op=update,status=done`，用户要求保留的用 `status=kept` 并写明原因。该工具只登记状态，不会自动删除资源。
- 台账只写资源类型、目标、位置和脱敏说明；不要写口令、令牌、私钥、Cookie 或其他秘密值。未完成项另写责任人、风险和后续期限。
- 交付报告区分已完成、被阻断、未测试和用户要求保留的资源。
- 保留可复核证据，同时对敏感字段做脱敏。

## 5. 立即停止条件

范围外资产、第三方服务边界不清、意外访问真实个人数据、服务中断迹象、权限超出预期、不可回滚写操作、凭据泄露或用户撤回授权。
