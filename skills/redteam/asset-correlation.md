# 资产关联与归属证据

目标是把“看起来相关”与“已经证明归属”分开。关系图谱用于整理证据，不自动授予测试权限，也不自动产生漏洞或得分。

## 1. 先核对范围

- 开始前用 `redteam_scope_review(allowed=...)` 对当前项目已登记资产与用户明确提供的允许范围做离线核对。
- 该工具只核对文本范围，不验证所有权或授权；域名解析、证书匹配、ASN 相同都不能替代用户授权。
- CDN、云托管、共享证书、共享 IP、同 ASN、相同 favicon、相同标题、同一 /24 只作为线索。不能据此把邻居资产纳入范围。
- 第三方供应商、公共设施、个人资产或无法确认归属的资产，保持线索状态，不主动探测。

## 2. 关系类型

- `resolves`：域名解析到 IP（domain → asset）。
- `contains`：已确认的网段包含 IP（segment → asset）。
- `exposes`：资产开放端口或服务（asset → port/service）。
- `shares_cert`：两个端点出现相同证书标识；它只表示共享证书，不表示同一所有者。
- `trusts`：有文档或配置证据支持的信任关系；没有证据时不要创建。

先用 `redteam_asset_query` 或 `redteam_asset_get` 读取已有记录，使用返回的真实 ID。需要建立关系时调用 `redteam_asset_link`，填写 `src_kind`、`src_id`、`dst_kind`、`dst_id`、`relation`，并按证据强度填写 `confidence`（0–1）。不要猜测或手工编造 ID。

## 3. 归属证据分级

- **T0 · 直接证据**：用户明确列入授权范围，或有可核验的组织官方资料直接证明归属。仍须满足本次任务的授权范围。
- **T1 · 多项强佐证**：例如证书主体、官方域名、注册信息、合同/运维资料等多项独立证据相互印证。T1 不是自动授权。
- **T2 · 线索**：同 C 段、同 ASN、相同 favicon、相同页面标题、共享 CDN/云平台、历史 DNS 等。只能用于后续人工核验。
- **T3 · 无关或排除**：有证据表明属于其他单位、个人或公共服务。标记排除，不探测。

不要把“同 C 段”升级为归属证明；也不要把共享证书、共享托管误判为 T0。证据冲突时降级并保留冲突说明。

## 4. 记录与复核

- 用 `redteam_asset_test` 的 `test` 追加关系判断、证据 URL/文件、采集时间、分级和未解决问题；不要覆盖已有测试记录。
- 关系边只记录可复核事实，备注中区分“观察到的关系”和“推断”。
- 截图只在确有必要时通过 `redteam_shot_add` 保存；先遮蔽个人信息、凭据、令牌和无关第三方数据。
- 主动验证前再次核对允许范围；只做证明当前假设所需的最小请求，并遵守用户指定的速率和时间窗口。

## 5. 交付格式

每个重要关系至少说明：源资产、目标资产、关系类型、证据来源、采集时间、置信度、归属分级、范围核验结果和仍待确认的问题。

不要仅凭图谱连通性推断可横向访问、存在漏洞或已经突破边界。只有实际、授权且可复核的访问证据才能支持相应结论。
