# 带外回调验证

本技能只验证受控测试请求是否触发预期 DNS/HTTP 回调。回调命中不自动证明命令执行、内网访问或数据泄露。

## 1. 前置条件

- 用户明确授权目标入口和测试时间窗。
- 回调域名/服务由用户控制或明确授权，且只记录必要的时间、协议、来源地址和随机 token。
- 每个测试用例使用独立、不可预测的 token；不把目标单位名称、账号或个人信息放入域名和路径。
- 先记录基线，排除浏览器预取、代理、扫描器和第三方安全服务产生的噪声。

## 2. 验证步骤

1. 为本次测试生成唯一 token，并确认回调服务只接受/记录该 token。
2. 在测试环境中提交无害的 URL/域名标记；不要将命令、文件路径、凭据或数据编码进回调地址。
3. 在预先约定的时间窗内查看 DNS/HTTP 事件，关联 token、时间、来源和原始测试请求。
4. DNS 命中只证明发生解析；HTTP 命中只证明发生了对应 HTTP 请求。只有能排除预取、代理和其他中间环节，才能归因到目标应用。
5. 没有回调时记录“未观察到回调”，不要直接判定不存在漏洞；也不要为了获得回调而升级为命令执行或读取内网资源。

## 3. 证据与判定

- 使用 `redteam_asset_test` 追加 token 标识、测试窗口、协议、事件时间、来源和噪声排除情况。
- 有明确安全影响时使用 `redteam_vuln_add`；单次 DNS 解析通常只能作为 candidate 证据。
- 只有在授权测试环境中可重复、且能证明具体应用行为时才标记 confirmed。
- 不保存完整请求中的敏感参数，不记录回调携带的环境变量、文件内容或其他数据。

## 4. 收尾

测试结束后停止本次回调监听，并按用户的数据保留政策处理自己控制的回调日志；保留必要的审计摘要。不得删除目标系统日志或隐藏测试活动。

不通过 OOB 通道执行 shell 命令、下载文件、持久化、内网探测或数据外传。
